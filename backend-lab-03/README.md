## 6. API Endpoints

| Method | Path | Purpose | Successful status |
|---|---|---|---:|
| GET | `/books/` | List books, optionally filtered and sorted | 200 |
| GET | `/books/:bookId/` | Get one book by ID | 200 |
| POST | `/books/` | Create a book | 201 |
| PUT | `/books/:bookId/` | Replace a book's details | 200 |
| DELETE | `/books/:bookId/` | Delete a book | 200 |

In a URL, `:bookId` is a placeholder. Replace it with a real ID, for example `/books/1/`.

### GET `/books/` query parameters

| Parameter | Default | Description and validation |
|---|---|---|
| `search_q` | No search | Partial match against the book title |
| `order_by` | `title` | Allowed columns: `id`, `title`, `author`, `price`, `pages` |
| `order` | `ASC` | `ASC` or `DESC` |
| `limit` | `10` | Positive integer maximum number of rows |
| `offset` | `0` | Non-negative integer number of rows to skip |
| `min_price` | No minimum | Non-negative integer lower price bound |
| `max_price` | No maximum | Non-negative integer upper price bound |

Example combining search, sorting, pagination, and a price range:

```text
http://localhost:3000/books/?search_q=The&order_by=price&order=DESC&limit=2&offset=0&min_price=250&max_price=400
```

Search text, filter values, IDs, pagination values, and book data are passed to SQLite using `?` placeholders. Sort columns cannot use value placeholders, so `order_by` is checked against an explicit allowlist; `order` is also validated before being included in the SQL.

### POST `/books/` example body

Choose **Body → raw → JSON** in Postman:

```json
{
  "title": "Postman Test Book",
  "author": "Nishant Kumar Thakur",
  "price": 350,
  "pages": 200
}
```

A successful response has status 201 and includes a generated `bookId`.

### PUT `/books/:bookId/` example body

Use the ID returned by POST:

```json
{
  "title": "Updated Postman Test Book",
  "author": "Nishant Kumar Thakur",
  "price": 375,
  "pages": 210
}
```

### Validation and error responses

| Status | Meaning | Example response |
|---:|---|---|
| 200 | GET, PUT, or DELETE succeeded | `{"message":"Book updated successfully."}` |
| 201 | Book created | `{"message":"Book created successfully.","bookId":11}` |
| 400 | Invalid ID, body, or query parameter | `{"message":"Title is required."}` |
| 404 | Book or route not found | `{"message":"Book not found."}` |
| 500 | Unexpected server/database error | `{"message":"Unable to retrieve books."}` |

Title and author must be non-empty strings. Price must be a non-negative integer; numeric strings containing an integer are also accepted. PUT requires a valid title, author, price, and positive page count. Invalid requests return a JSON `message` and do not change the database.

## 8. Debugging Exercises

### Error 1: `EADDRINUSE`

**Cause:** A second process is trying to listen on a port already used by the first server.

**Safe reproduction:** While one Lab 3 server is running, open a second terminal in this folder and run:

```powershell
node .\server.js
```

The second process should report `EADDRINUSE` for port 3000. Find the process listening on that port:

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen | Select-Object LocalPort,OwningProcess
Get-Process -Id <PID>
```

Replace `<PID>` with the number returned by the first command. Stop a server you started with `Ctrl+C` in its terminal. Alternatively, start this app on another port:

```powershell
$env:PORT = 3001
npm run dev
```

After stopping it, remove the temporary port setting with `Remove-Item Env:PORT`.

### Error 2: Wrong `require()` path

**Safe reproduction:**

```powershell
node -e "require('./missing-helper')"
```

Node reports that it cannot find the module because that relative file does not exist. A path beginning `./` is relative to the file doing the import. Check spelling and folder location. For an installed package, use the package name:

```javascript
const { open } = require("sqlite");
```

For a real neighboring project file, use its correct relative path, for example `require("./helper")` when `helper.js` is in the same folder.

### Error 3: `no such table`

**Safe reproduction:** This read-only command deliberately uses the wrong plural table name:

```powershell
sqlite3 .\books.db "SELECT * FROM books;"
```

SQLite reports `no such table: books`. Inspect the actual table and schema:

```powershell
sqlite3 .\books.db ".tables"
sqlite3 .\books.db ".schema book"
```

The correct table is `book` (singular). Also check the server startup message after `Using database:` to make sure it ends with this Lab 3 folder's `books.db`, not an empty or unrelated database file.

### Error 4: Missing `await`

**Cause:** `db.get()` is asynchronous and returns a Promise. Without `await`, the variable is the pending Promise, not the database row; reading `promise.title` does not give the title.

**Safe, read-only demonstration:**

```javascript
const pendingBook = db.get(
  "SELECT * FROM book WHERE id = ?",
  [1]
);
console.log(pendingBook.title); // undefined: this is still a Promise

const book = await pendingBook;
console.log(book.title); // The Alchemist
```

The route must wait for the query before using the row:

```javascript
const book = await db.get("SELECT * FROM book WHERE id = ?", [bookId]);
```

## 9. Problems Faced and Solutions

- Opening `/` returned `Cannot GET /` because the API defines `/books/`, not a home page. Use `http://localhost:3000/books/`.
- Postman reported `getaddrinfo ENOTFOUND books` when the URL was not the complete local address. Enter `http://localhost:3000/books/` in the URL field.
- Postman once returned `Cannot POST /books/` while pointed at a server that did not have the Lab 3 route. Restarting from the `lab-03` folder fixed it; the startup log should show the `lab-03\books.db` path.
- During implementation, a whitespace or boolean price could be converted to a number by JavaScript. POST/PUT validation now accepts only non-negative integer prices (including numeric strings) and returns 400 for invalid values.
