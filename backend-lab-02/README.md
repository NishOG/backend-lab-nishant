## 5. Database Setup

The database contains a `book` table with these columns: `id` (primary key), `title`, `author`, `price`, and `pages`.

From the project folder, create the table and insert the sample records using the SQLite CLI:

```powershell
sqlite3 .\books.db ".read schema.sql" ".read seed.sql"
```

The seed SQL explicitly inserts 10 sample rows through SQLite CLI; no JavaScript seed code is used. The inserts use `INSERT OR IGNORE`, so re-running the seed command does not duplicate rows with the same IDs.

Display and verify the records:

```powershell
sqlite3 .\books.db ".headers on" ".mode column" "SELECT id, title, author, price, pages FROM book ORDER BY id;"
sqlite3 .\books.db "SELECT COUNT(*) FROM book;"
```

To inspect database changes after API requests, run:

```powershell
sqlite3 .\books.db ".headers on" ".mode column" "SELECT * FROM book ORDER BY id;"
```

## 6. Implementation

- `server.js` opens `books.db` asynchronously with `sqlite` and the `sqlite3` driver.
- `initializeDBAndServer()` waits for the database connection before starting Express on port 3000.
- `GET` routes read records, `POST` inserts a book, `PUT` updates one, and `DELETE` removes one.
- Request bodies are checked before inserts or updates. IDs must be positive integers.
- SQL statements use `?` placeholders and pass values separately as parameters. This keeps user input from being treated as part of the SQL command, helping prevent SQL injection.
- A missing book returns a JSON error with status 404. Invalid IDs or book data return status 400. Unexpected request/database errors return status 500.

## 8. API Endpoints

| Method | Path | Purpose | Expected Status |
|---|---|---|---:|
| GET | `/books/` | Get all books | 200 |
| GET | `/books/:bookId/` | Get one book by ID | 200, or 404 if missing |
| POST | `/books/` | Add a book | 201, or 400 for invalid data |
| PUT | `/books/:bookId/` | Update a book | 200, 400 for invalid data, or 404 if missing |
| DELETE | `/books/:bookId/` | Delete a book | 200, or 404 if missing |

### POST request body

Send as raw JSON in Postman:

```json
{
  "title": "Postman Test Book",
  "author": "Nishant Kumar Thakur",
  "price": 350,
  "pages": 240
}
```

The response has status 201 and returns the created book, including its generated `id`.

### PUT request body

Use the ID returned by POST in the URL, for example `/books/11/`. Send the replacement values as raw JSON:

```json
{
  "title": "Updated Postman Test Book",
  "author": "Nishant Kumar Thakur",
  "price": 399,
  "pages": 250
}
```

The response has status 200 and returns the updated book.

For an error check, `GET /books/9999/` returns status 404 and `{"error":"Book not found."}`. An invalid POST or PUT body returns status 400 with a JSON error.
